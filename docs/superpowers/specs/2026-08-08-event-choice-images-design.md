# 事件與選項圖片完整化設計

## 目標

為所有內建遊戲內容補齊圖片，同時保留目前已存在的事件圖片。涵蓋主線、人物事件、一般事件、支線任務、日常活動、商店購買及戰鬥行動。每個選項同時在按鈕內顯示縮圖，並在結算畫面顯示大型結果圖。

玩家建立的自訂卡牌不在預先產圖範圍內，使用一致的通用備援圖片。

## 視覺規格

- 延續現有現代東亞海港犯罪黑色電影風格：近黑綠、深藍綠、水泥灰，少量琥珀燈光與薄荷綠提示光。
- 不加入品牌、圖片內文字、浮水印、過量霓虹或未來科技元素。
- 涉及既有人物時，以 `assets/images/characters/` 的角色圖作為外觀參考，維持髮型、服裝、年齡與整體氣質。
- 缺少主圖的事件生成桌機 16:9 與手機 4:5 兩個重新構圖的版本。既有事件圖片不得覆寫或重新生成。
- 每個內建選項生成一張專屬 3:2 WebP 主圖，描繪該選項即將採取的具體行動。
- 選項按鈕與結果畫面共用同一張選項主圖：按鈕使用縮圖呈現，結果畫面顯示完整大圖。
- 能力檢定成功或失敗共用同一張選項圖片。

## 結算畫面

結果畫面頂端顯示大型「成功」或「失敗」狀態文字。狀態文字由 HTML 與 CSS 繪製，不寫入生成圖片：

- 使用明顯大於結果標題與內文的字級、粗字重與高對比色彩。
- 成功與失敗使用可辨識的不同色彩，並保留文字標籤，不能只靠顏色傳達。
- 桌機與手機皆保持醒目，且不遮擋選項結果圖片的主要人物或動作。
- 非能力檢定或系統直接結算的內容，依既有 `lastResult.success` 狀態顯示；若沒有成功狀態，顯示中性的「結果」。

## 資產清單與命名

實作前由內容資料自動建立資產清單，逐項標記：

1. 已有事件主圖，直接沿用。
2. 缺少事件主圖，需要桌機與手機版本。
3. 內建選項，需要一張專屬主圖。
4. 動態或自訂內容，使用通用備援圖。

事件圖維持 `{場景}-desktop.webp` 與 `{場景}-mobile.webp` 命名。選項圖存放於 `assets/images/choices/`，使用穩定且不衝突的事件與選項 ID，例如 `signal-trace.webp`。若不同內容層級可能出現相同 ID，檔名必須包含完整父層 ID。

資產清單也記錄每張圖片的替代文字、內容分類與是否沿用既有資產，作為生成、程式映射和完整性測試的共同來源。

## 程式架構

建立集中式圖片映射模組，使用穩定 ID 查詢事件圖與選項圖。畫面程式不維護分散的硬編碼路徑。

共用圖片元件負責：

- 事件桌機／手機響應式圖片。
- 選項按鈕縮圖。
- 結算畫面大型圖片。
- 延遲載入、替代文字與載入失敗備援。

事件、人物事件、支線節點、活動、商店與戰鬥按鈕都透過相同介面提供父層 ID 與選項 ID。玩家選擇後，結算資料保存可穩定重建圖片鍵值的來源與選項 ID；重新整理或載入存檔後仍能顯示正確結果圖。

## 資料流程

1. 內容資料提供事件或活動 ID、選項 ID 與文案。
2. 圖片映射模組使用完整鍵值查找選項圖片。
3. 選項畫面將圖片顯示為按鈕縮圖。
4. 玩家選擇後，遊戲引擎將完整圖片鍵值寫入 `lastResult`，不保存大型圖片資料本身。
5. 結算畫面由鍵值查找相同圖片並顯示大圖，再依成功狀態顯示大型狀態文字。

既有存檔若沒有圖片鍵值，畫面可從既有的選擇資訊重建；無法重建時使用分類備援圖，不能造成存檔驗證失敗。

## 生成與處理流程

- 使用內建 AI 圖片生成工具，依主線、人物事件、一般事件、支線、日常、商店與戰鬥分批生成。
- 每批使用固定的美術規格；人物場景加入既有角色圖作為參考。
- 每個不同選項使用獨立提示，不以同一提示的多張變體代替不同內容。
- 產圖後檢查主體、動作、構圖、人物一致性、禁用文字與浮水印。
- 最終圖片移入專案，轉為 WebP、移除中繼資料並壓縮；不得只保留在生成工具的預設位置。
- 既有資產不得覆寫。若需要修改新生成資產，使用版本化暫存名稱，確認後再更新映射。

## 效能與備援

- 事件與選項圖片採延遲載入，不預先下載玩家尚未看到的整套資產。
- 選項按鈕使用 CSS 固定比例與 `object-fit`，避免版面跳動。
- 單張圖片以視覺品質可接受的最小 WebP 體積為目標；生成後以自動檢查列出超過資產預算的檔案。
- 圖片映射缺漏、檔案不存在或瀏覽器載入失敗時，保留完整文字按鈕與結果內容，遊戲流程不得中斷。
- 自訂卡牌與無法預先列舉的動態組合使用分類備援圖片。

## 驗證

自動測試與資產檢查必須驗證：

- 所有內建事件與可列舉選項都有圖片映射。
- 映射指向的檔案確實存在，檔名沒有碰撞。
- 既有圖片未被覆寫或移除。
- 選擇後的 `lastResult` 保存正確圖片鍵值；舊存檔仍能載入。
- 圖片缺失時仍可顯示文字並完成選擇。
- 成功、失敗與中性結果都顯示正確且醒目的狀態文字。

視覺驗收涵蓋桌機與手機：選項縮圖不遮蔽文字、大圖比例正常、狀態文字醒目、不遮擋主要內容。另按分類抽查生成圖片的人物一致性、動作符合選項、無不需要的文字與浮水印。

## 非目標

- 不重新生成或覆寫任何既有事件、人物、隊員、領地與首頁圖片。
- 不為成功和失敗分別生成圖片。
- 不為玩家日後建立的任意自訂卡牌即時呼叫 AI 產圖。
- 不改動事件數值、選項效果、劇情結果或遊戲平衡。
