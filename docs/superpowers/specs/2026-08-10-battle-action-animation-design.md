# 戰鬥動作動畫設計

## 目標

將已核准的狄菲近身二連擊與手槍快速射擊放入正式戰鬥畫面，並建立可擴充至掩護、駭入、撤離與其他隊員招牌動作的共用動畫插槽。

## 呈現結構

- 敵人名稱、意圖、生命與戰鬥通報放在動畫區上方。
- 中央區只顯示透明全身角色、敵方剪影與命中效果，不放長篇說明。
- 出勤隊員人像與能力資訊保留在戰鬥畫面下方。
- 桌機與手機共用同一套透明 WebP；CSS 只調整角色尺寸、位置及特效座標。

## 動作與角色

- `attack`：狄菲執行手槍快速射擊，依序為低位戒備、舉槍、擊發、後座、回復。
- `brawl`：狄菲執行左直拳接左旋踢，沿用已核准的戒備、左直拳、踢擊蓄力與左旋踢姿勢。
- `hack`、`guard`、`flee` 暫時維持立即結算；動畫登錄表預留相同介面，之後加入適合的核心隊員與素材。

## 結算流程

玩家按下有動畫的戰鬥動作時，程式先呼叫一次戰鬥引擎取得下一個狀態，從前後狀態計算實際敵方傷害與我方受傷，再鎖定戰鬥按鈕並播放時間軸。動畫結束後直接套用先前算好的狀態，不再次呼叫亂數。若戰鬥因此勝利或失敗，動畫播完才切換結果畫面。

沒有動畫定義的動作維持目前的立即結算。播放期間再次點擊不會產生第二次行動；發生錯誤時解除鎖定並顯示既有錯誤訊息。

## 可及性與效能

- 圖片使用透明 WebP，避免重複的桌機與手機檔案。
- 動畫舞台提供可讀的 `aria-label`；戰鬥通報使用 `aria-live="polite"`。
- 使用者偏好減少動態時，縮短時間軸並停用鏡頭晃動、彈殼與連續位移。
- `index.html` 仍載入預先建置的 `dist/game.bundle.js`，可直接雙擊離線遊玩。

## 驗收條件

- `attack` 會完整播放射擊姿勢、槍口火光、彈道、彈殼與敵方受擊，再結算一次。
- `brawl` 會完整播放左直拳與左旋踢，再結算一次。
- 動畫顯示的傷害數字等於戰鬥引擎實際扣除的敵方戰力。
- 播放期間所有戰鬥按鈕停用，結束後不會卡死或重複扣血。
- 760px 以下版面沒有水平溢出，人物全身與武器不被裁切。
- 全部 Node 測試、離線建置與圖片稽核通過。
